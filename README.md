# ShopPilot

> 基于 Agent 的智能导购系统 · Vue3 + Spring Boot + Python LangChain

在已有电商数据之上构建 AI 导购前台，让用户用自然语言完成「说需求 → 得到推荐 → 直接下单」的完整购物流程。

## 要解决的问题

传统电商是「人找货」：用户必须自己想清楚要什么、自己拆关键词、自己比对参数。但真实购物场景里，用户往往只有一个模糊的意图——「想给女朋友买个生日礼物，300 以内」——却不知道对应什么商品、该搜什么词。

ShopPilot 把这段翻译和决策的工作交给 Agent：用户只需表达意图，Agent 负责理解、筛选、对比、解释理由，并在用户确认后直接代办交易动作。

## 核心能力

| 能力 | 说明 |
|---|---|
| 场景化选品 | 把抽象意图（生日礼物、露营装备）映射到具体品类，结合预算与场景排序 |
| 多品对比 | 针对具体使用场景做取舍，而非罗列参数表 |
| 槽位澄清 | 需求不全时主动追问，信息齐备才执行检索 |
| 交易代办 | 支持「再来一单」「加入购物车」等真实业务动作 |

## 架构

```
Vue3 (5173) ──HTTP/SSE──▶ Java (8080) ──HTTP/SSE──▶ Python Agent (8000)
                              ▲                            │
                              └────── 工具反向调用 ──────────┘
```

- **Vue3 前端**：对话界面、商品卡片渲染、SSE 流式输出、会话历史
- **Java 后端**：唯一对外入口，鉴权、会话持久化、商品与订单业务、交易一致性
- **Python Agent**：无状态服务，意图识别、混合检索、LangGraph 编排、工具调用

职责边界：Java 是唯一有状态层，Python 不碰数据库、不解析 JWT。数据库权限不下放。

## 技术要点

- **混合检索**：向量召回 + 结构化过滤（价格/库存/上架）+ 重排序，解决纯向量检索在电商场景下的失效问题
- **双 RAG**：商品检索走 pgvector，导购知识走进程内向量库，两类问题分流
- **会话记忆**：Redis 存最近 N 轮原文 + 超阈值自动摘要压缩，上下文不无限膨胀
- **上下文工程**：中间件按条数 + 字符数双预算裁剪，保证 tool_call 与 tool_result 不被切断
- **多模态**：图片先经 VL 模型转文本描述，后续轮次复用，避免重复传图
- **MCP 接入**：Tavily 官方 MCP server（stdio）提供联网检索，站内商品库覆盖不到时兜底
- **槽位状态机**：LangGraph 管理必填槽位，缺失则走追问分支
- **SSE 流式透传**：Python → Java（WebFlux Flux）→ 前端逐字渲染，中间态可感知
- **反向工具调用**：Python 通过内部接口回调 Java，写操作需用户二次确认

## 分阶段路线

| 阶段 | 交付 | 验收 |
|---|---|---|
| P1 | 单轮对话 + 向量检索 + 商品卡片 | 说「300 以内的蓝牙耳机」能出真实商品卡片 |
| P2 | 结构化过滤 + 槽位追问 | 「买礼物」会反问预算；「500 以内」不推 5000 的 |
| P3 | 交易工具（加购 / 再来一单） | 说「再来一单」能真的进购物车 |
| P4 | 多品对比 + 埋点评估 | 能对比两款；后台能看到点击率 |
| P5 | 流式 + 会话持久化 + 前端打磨 | 逐字输出，历史可回看 |

## 明确不做

商品管理后台、支付渠道对接、物流履约——复用已有电商项目。本项目只聚焦「对话式导购」这一层。
