### 3306 建不了数据源的真正原因（三层叠加，非端口冲突）

1. MySQL 的 Windows 服务已注册但处于 **Stopped**，当前用户无管理员权限启动（`Start-Service` 报 `Cannot open MySQL service`）
2. 直接跑 mysqld 会 abort：默认 PID 文件名取**主机名**，本机主机名是中文 → 编码成 `??????_.pid` → `Permission denied`

**解决**：`pilot-infra/scripts/mysql-start.sh`，用 `exec mysqld` **前台阻塞**运行 + 显式 `--pid-file`/`--log-error` 指向项目内 `.runtime/mysql/`（全 ASCII 路径）。

### MySQL 9.7 兼容性（与 5.7/8.0 教程不同，已实测）

| 差异 | 现象 | 应对 |
|---|---|---|
| `MD5()` 已移除 | `FUNCTION MD5 does not exist` | 用 `LEFT(SHA2(x,256),32)` |
| `VECTOR` 类型存在但 `DISTANCE()` 不可用 | 函数不存在 | 余弦相似度在 Java 应用层算 |
| 向量列不能建索引 | `using hnsw` 语法错误；BTREE 报 Non-scalar | 同上 |

**架构影响**：原计划的 PostgreSQL+pgvector 因 Docker 未装而起不来，改为 **MySQL 单库 + 应用层算相似度**。`sp_product_embedding` 表结构与 pgvector 版同构，将来迁移只换存储实现。

## DataGrip 数据源接入（19:37~19:50）

### 做法

预置项目级配置，不用手填连接串：
- `.idea/dataSources.xml` — 连接参数、驱动、URL
- `.idea/dataSources.local.xml` — 用户名、introspection-scope、secret-storage

**密码无法外部写入**：DataGrip 用 KeePass 加密库（配置目录 `c.kdbx`），主密钥由 IDE 管理，手写明文或伪造密文都无效。首次连接时手动输 `1234` 并勾 Save password。这是设计限制，不是配置缺失。

### 关键坑：characterEncoding 不能写 utf8mb4

实测报错 `Unsupported character encoding 'utf8mb4'`。Connector/J 不认 `utf8mb4` 这个名字，**必须写 `UTF-8`**，驱动内部会自动映射到 MySQL 的 utf8mb4 字符集。这个坑很隐蔽，因为 MySQL 侧的字符集名确实叫 utf8mb4。

### JDBC URL 完整参数（每个都有明确目的）

```
characterEncoding=UTF-8        中文不乱码（不能写 utf8mb4）
serverTimezone=Asia/Shanghai   避免 DATETIME 偏移 8 小时
allowPublicKeyRetrieval=true   MySQL 8+ caching_sha2_password 必需
useSSL=false                   本地连接免握手
tinyInt1isBit=false            TINYINT(1) 按数字读，与后端 R2dbcConfig 对齐
```

`tinyInt1isBit=false` 必须与后端一致，否则 DataGrip 显示 true/false、后端拿 0/1，排查时会误判。

### 验证方式

`pilot-infra/scripts/verify-datasource.sh` —— 用 DataGrip 自带的 `mysql-connector-j-9.7.0.jar` 跑真实连接，等价于 IDE 的 Test Connection。实测结果：18 张表、中文正常、`on_shelf=1 (Integer)`、场景映射正确。

注意：Java 在 Windows 终端输出中文需加 `-Dstdout.encoding=UTF-8`，否则全是问号。

## DataGrip「数据源在但展开空白」诊断（19:53~20:05）

### 确诊依据（三处互证）

1. **图标颜色**：截图里数据源图标是 `RGB(0,175,255)` 浅蓝 = 未连接（连上是绿色）
2. **缺模型文件**：`.idea/dataSources/` 下只有 `data_sources_history.xml`，没有 `<uuid>.xml`。对比 huinong-mall 有 60KB 的 `2c9f5b52-...xml`
3. **日志无连接**：`idea.log` 只有 `No model loaded for: shop_pilot@localhost`，**19:43 之后没有任何 `Connecting to: jdbc:` 记录**
4. **MySQL 侧反查**：`information_schema.processlist` 只有我自己的连接，证明 DataGrip 从未连上来

### 根因

密码从未保存。证据：`c.kdbx` 时间戳停在 18:48（配置是 19:39 才建的），`c.pwd` 里搜不到数据源 UUID。

**DataGrip 没有凭据就不发起连接**，不是连接失败——是压根没试。所以界面上不会有报错，只表现为空白。

### 修复

在 Database 面板右键 → `Properties` → 填密码 → 勾 Save password → Test Connection。
（如果点 Connect 不弹密码框，走 Properties 一定能输）

### 另一个坑：不要预填 <database-info>

`dataSources.local.xml` 里的 `<database-info product="MySQL" version="9.7.0">` 是 introspection **成功后** IDE 写入的探测结果，不是配置项。预填会让 DataGrip 以为已探测过而跳过首次连接，症状一模一样。已从文件里移除。

### 诊断方法论（可复用）

IDE 数据源问题的排查顺序：**图标颜色 → 模型文件是否存在 → 日志有无连接尝试 → 数据库侧 processlist 反查**。
这四步能区分「配置错」「密码缺」「网络不通」「根本没连」四种情况，比反复点重试有效。

### 设计决策：为什么不用卡片网格

常见电商列表是「左筛选栏 + 右卡片网格」。这里刻意换成**左窄索引 + 右账本行**：
- 卡片网格的注意力集中在图片上，但种子数据的 `cover_url` 指向 `cdn.shoppilot.dev`（**域名不存在**），图片必然 404
- 改用「品类首字 + 由品类名 hash 派生的色相」做视觉锚点，天然唯一且不需要资源
- 行式布局的扫读路径是单列（序号→标题→已售→价格），比网格更快；价格用等宽字体右对齐

### 三种状态的实现要点

| 状态 | 触发 | 实现要点 |
|---|---|---|
| 加载中 | 首次请求 | 骨架屏行数与真实行 grid **完全一致**，否则数据到位会横向跳动 |
| 空数据 | `?keyword=zzzznotexist` | 与失败严格区分：文案给「清空筛选」而非「重试」，并标注 `total=0` 不是故障 |
| 请求失败 | 停后端 / mock 500 | 展示 HTTP 状态 + 业务码 + traceId + 耗时，按 `status===0` 和 `isAuthError` 给不同排查提示 |
